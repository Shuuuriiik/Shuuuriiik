# MikroTik: резервный LTE-канал через рекурсивные маршруты

Классика: два дефолтных маршрута с разной `distance` и `check-gateway=ping` на шлюз провайдера. Проблема в том, что шлюз провайдера обычно **пингуется всегда** — даже когда дальше него интернета нет. Роутер думает, что всё хорошо, а офис сидит без связи.

## Идея

Проверяем не шлюз, а **внешний адрес** (например, `8.8.8.8`), который достижим только через основной канал. Если он перестал отвечать — основной маршрут становится неактивным, трафик уходит в LTE.

## Настройка (RouterOS 7)

Допустим, основной провайдер — `ether1`, шлюз `203.0.113.1`, резерв — `lte1`.

```
# 1. Хост-маршрут до «маяка» только через основного провайдера
/ip route add dst-address=8.8.8.8/32 gateway=203.0.113.1 scope=10 comment="beacon ISP1"

# 2. Основной дефолт — рекурсивно через маяк
/ip route add dst-address=0.0.0.0/0 gateway=8.8.8.8 target-scope=11 \
    check-gateway=ping distance=1 comment="WAN1 recursive"

# 3. Резерв через LTE
/ip route add dst-address=0.0.0.0/0 gateway=lte1 distance=2 comment="WAN2 LTE"
```

Ключевое — `scope=10` у хост-маршрута и `target-scope=11` у дефолтного: так роутер разрешает рекурсивный поиск шлюза.

## Если основной канал по DHCP

Шлюз меняется — статикой не пропишешь. Отключи автоматический дефолт у DHCP-клиента и добавляй маршрут скриптом:

```
/ip dhcp-client set [find interface=ether1] add-default-route=no script={
  :if ($bound=1) do={
    /ip route remove [find comment="beacon ISP1"]
    /ip route add dst-address=8.8.8.8/32 gateway=$"gateway-address" scope=10 comment="beacon ISP1"
  }
}
```

## Грабли

- **Маяк не используй как DNS.** Если 8.8.8.8 — твой DNS-сервер, при падении основного канала DNS тоже отвалится (маршрут до него только через ISP1). Возьми для DNS `1.1.1.1` или `77.88.8.8`.
- **Один маяк — одна точка отказа.** Для надёжности делают два маяка (8.8.8.8 и 1.1.1.1) и два рекурсивных маршрута с одинаковой distance.
- **Проверка раз в 10 секунд.** `check-gateway` ждёт пару пропущенных пингов, так что переключение занимает ~10–20 секунд. Для офиса нормально.
- **NAT.** Не забудь masquerade на обоих интерфейсах — удобнее через interface-list `WAN`.

## Проверка

```
/ip route print where dst-address=0.0.0.0/0
/tool traceroute 1.1.1.1 count=1
```

Выдерни кабель из `ether1` (или заблокируй 8.8.8.8 на стороне провайдера фильтром) — активным должен стать маршрут через `lte1`.
